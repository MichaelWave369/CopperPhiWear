# ΦVault — V1.0 development increment
Start the existing local server and open the launcher. ΦVault stores named immutable snapshots of the existing garment, hybrid and laboratory JSON formats. A shared version-1 envelope does not replace the underlying module schemas. Save/load controls are embedded in those editors; fabrication can load a garment snapshot and ΦWear can save a planned laboratory register. Loading requires explicit confirmation. Save creates a new record; delete requires confirmation. Backup import merges validated records, is idempotent for identical IDs, and rejects conflicting IDs without changing the vault.
Browser localStorage is origin/profile-specific and may be erased or unavailable. Writes use the Web Locks API to serialize cooperating same-origin tabs; unsupported browsers fail closed and can still use original file exports. Quota errors are reported. Limits: 100 records, two million serialized characters, individual module schema bounds. No encryption, accounts, cloud sync or automatic saves. Do not enter personal health information. Save portable JSON backups. Other module reports remain file-based. Automated model tests cover storage round trips, merges, validation, conflicts and errors with fake storage, not actual browser persistence or concurrent tabs. Physical research remains pending.
